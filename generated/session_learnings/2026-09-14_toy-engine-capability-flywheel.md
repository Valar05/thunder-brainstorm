# Toy Engine Capability Flywheel

**Date:** 2026-09-14
**Status:** active brainstorm / production philosophy

## Core loop

Drew's stated strategy is not primarily to make games as monolithic projects. It is to make **small toys** that are useful, shippable, and delightful enough to stand on their own. Those toys accumulate into an engine. The engine lowers the cost of the next experiment or game.

```text
TOY
-> SHIPPABLE CAPABILITY
-> ENGINE ACCUMULATION
-> LOWER COST OF NEXT IDEA
-> MORE TOYS / MORE OPTIONAL GAMES
```

The important consequence is that a toy does not need to justify itself by becoming a complete game. It can succeed by adding durable capability.

## Capability compounding

Let `E_n` be the reusable capability set after `n` shipped toys. For a future idea `I`, production cost is not fixed:

```text
Cost(I | E_n) <= Cost(I | E_{n-1})
```

when the new engine capability overlaps the idea's needs.

The strategic output of a toy is therefore twofold:

```text
toy value = immediate utility / delight + reusable capability
```

A toy that is merely useful can still increase the capability base. A toy that is also creatively exciting creates extra upside, but creativity is no longer required for the work to count.

## Optional creativity

This changes the emotional contract of making things.

The minimum gate becomes:

```text
Is it useful?
Is it shippable?
```

Creativity becomes an upside rather than an obligation.

That matters because requiring every work unit to be original, meaningful, beautiful, or game-worthy turns creativity into a tax. A capability-first toy can be valuable without performing artistic significance on demand.

When delight appears, it rides on top of already-valid work.

## Escape from generic work grind

The attraction of this loop is not merely entrepreneurship or portfolio building. It is a different relation to labor:

- the work produces something concrete;
- the result can be inspected, shipped, reused, and improved;
- the work can bring joy without requiring joy for validity;
- successful work reduces the cost of future self-directed work;
- capability compounds instead of being consumed and reset by the next task.

The desired asymmetry is:

```text
TODAY'S WORK
should make
TOMORROW'S DELIGHT CHEAPER
```

rather than today's work merely purchasing permission to repeat the same labor tomorrow.

## Toy versus prototype

A prototype asks:

> Can this future product work?

A toy asks:

> Is this thing already worth touching?

A capability toy can do both, but its standalone usefulness is important. This prevents every experiment from becoming debt attached to a hypothetical future game.

## Relation to game auditions

The earlier game-audition doctrine fits inside this loop.

Instead of selecting a game and building its infrastructure, build the smallest toy that tests the game's interesting claim. If the claim survives, the toy may become part of the engine. If the game dies, the capability can remain.

```text
GAME IDEA
-> SMALL TOY AUDITION
-> useful? ship it
-> reusable? absorb it into engine
-> still exciting? grant the game another audition
```

Failure therefore need not produce a discarded prototype. It can produce infrastructure.

## Stronger production criterion

A proposed piece of work can be evaluated on three independent axes:

1. **Shippability** — can another person or future Drew actually use or inspect it?
2. **Capability gain** — does it lower the cost or increase the option space of future work?
3. **Delight** — does it create enough curiosity or pleasure to invite another move?

Only the first two are required for productive work. Delight is strategically valuable but not mandatory.

## Compact doctrine

> **Do not demand that every artifact become a game. Make toys that become capability. Let capability make games cheaper.**

> **Creativity is allowed to be optional because usefulness and shippability already make the work real.**

> **The best work does not merely finish a task. It lowers the price of the next delightful idea.**
