# Decomposing Game-Making from the Game Industry

**Date:** 2026-09-14
**Status:** active brainstorm / Bad House extension

## Core claim

Games are supposed to be joyful, but the economic systems around games can make the activity serve extraction rather than play. Attention, money, retention, labor, prestige, platform dependence, monetization pressure, and scarcity can all become structural demands that compete with the thing that made the medium worth loving.

The proposed escape is not merely to make a nicer game company. It is to **decompose the ability to make games from the industry that currently makes games**.

```text
GAME-MAKING CAPABILITY != GAME INDUSTRY
```

An engine that aggressively removes friction changes who is allowed to author play. The engine becomes a capability commons: a growing substrate of locomotion, interaction, animation, touch control, world generation, combat grammar, materials, UI, persistence, and other solved affordances that make the next game dramatically cheaper to attempt.

## Relation to Bad House theory

Bad House theory says a system becomes hostile when the inhabitant's activity increasingly serves the house more than the house serves the activity.

Applied to games, the failure mode is not simply 'games cost money.' The deeper inversion is:

```text
PLAY -> serves retention / extraction / monetization / platform goals
CREATION -> serves schedule / portfolio / market positioning / capital recovery
```

A healthier architecture reverses the direction:

```text
TOOLS -> serve creation
CREATION -> serves play / expression / learning / community
MONEY -> optional consequence, not the semantic owner of the work
```

Profit is allowed. Fame is allowed. Obscurity is allowed. None of them define whether the act was legitimate.

## The toy -> engine -> commons flywheel

Earlier doctrine:

```text
IDEA -> TOY -> CAPABILITY -> ENGINE -> CHEAPER NEXT IDEA
```

The new extension is:

```text
IDEA
-> SMALL SHIPPABLE TOY
-> REUSABLE CAPABILITY
-> LOWER CREATION FRICTION
-> MORE PEOPLE CAN AUTHOR
-> MORE FORMS OF PLAY BECOME CHEAP ENOUGH TO EXIST
-> CAPABILITY RETURNS TO THE ENGINE
```

The engine's success is therefore not measured only by whether it helps Drew ship a particular game. It is measured by whether authorship itself becomes easier to enter and cheaper to continue.

## Communal joy

If the engine makes creation cheap enough, joy stops being bottlenecked by the industrial production apparatus.

Someone may use the same capability to:

- make a commercial hit;
- make a one-evening toy for friends;
- make a strange personal game no market would fund;
- teach a child how interaction works;
- test one animation law;
- create something that nobody else ever sees.

These outcomes can coexist because the engine has separated **permission to create** from **economic proof that creation deserves to exist**.

Compact form:

> **The engine should make play authorable before it makes play profitable.**

## Creativity becomes optional, not compulsory

This complements the toy-engine doctrine. A useful, shippable capability is already valid work. Creativity can emerge from recombination rather than being demanded on schedule.

That matters because mandatory originality can become another Bad House: every work session must justify itself by producing novelty. A capability-first engine instead permits ordinary engineering to lower the cost of future creativity.

```text
TODAY: ship useful capability
TOMORROW: someone combines it unexpectedly
LATER: the combination becomes a game
```

## Decoupling thesis

The larger thesis is not 'destroy the game industry' and not 'money corrupts every game.' It is narrower and more testable:

> **The ability to create games should not depend on participating in the economic and organizational structures of the professional game industry.**

A successful engine increases the independence of the creative act from those structures.

This is analogous to earlier abundance-system observations around Blender: difficult capability can still be liberating when access remains open and understanding increases agency. The target engine should go further by attacking not only access cost but also authoring friction.

## Acceptance tests for the engine

The engine is moving in the intended direction when:

- a useful toy can ship without needing to become a whole game;
- capabilities survive the toy that produced them;
- a later project reuses prior work with materially lower effort;
- creators can express intent at a higher semantic level than raw implementation;
- unusual ideas become cheaper to test than to endlessly justify;
- commercial success is compatible with the system but not required for the artifact to count;
- another person can use accumulated capability without inheriting the original creator's entire workflow burden;
- the system makes it easier to author play than to optimize extraction.

## Compact doctrine

> **Do not merely make games outside the industry. Make the ability to make games less dependent on the industry.**

> **Joy becomes communal when authorship becomes cheap enough that permission is no longer scarce.**

> **The engine is not a game factory. It is a reduction in the price of having an idea.**
